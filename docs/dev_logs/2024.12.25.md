## 2024.12.25

Found a subtle bug in my code today.
Basically, it seemed as if submitting things quickly in the UI 
would lead to inconsistent states.
However, after fixing some things, it no longer appeared that 
the database was in an inconsistent state. In other words, 
no server side errors. But in the UI, it would add gaps 
and make updates disappear, but inconsistently.

Finally automated the testing, and figured out the issue.

* Click on a note to start editing. Div contenteditable becomes true.
* Finish editing, and click on another note to start editing.
* Everything seems fine, but then click on the + button to add a new note.
* The data from the first item I edited disappears, the second remains.
* But only happens some of the time, why?

So I had a timer set that, while the user is editing, would update the database 
every few seconds if the content being edited changed from the last time it was 
saved. This was to prevent data loss in case the user navigated away from the page.
Also, any time the user hit escape, or clicked (*almost*) anywhere outside the note,
it would close and immediately save the note.

I say *almost* because there was one exception to this. If you clicked directly 
on another note, the events to save the prior note were not firing. However, 
this wasn't immediately apparent because, unless you were moving quickly, the 
autosave would have already kicked in, so no data would be lost.
But, if you typed quickly and then quickly clicked on another note, the 
autosave wouldn't have kicked in yet, and the data would be lost. But, 
because we were not doing a refresh from the server for updates, the data would 
still appear to be there in the UI, but not in the database. And you would only 
see the "loss" of data (or rather, lack of having saved in the first place) 
for operations that caused a refresh from the server.

Once I turned off the auto-save, I was able to reproduce the issue consistently,
no matter how slowly I typed or switched items. Then I was able to automate it
and look at the server logs and see that there was only one save operation for 
the content update of the note, when there should have been two.

So anyway, bug isn't fixed yet, but at least I know what it is now.

1. Blur event on the note being edited.
2. User inactivity for k seconds + new unsaved content. But note stays in editing mode.
