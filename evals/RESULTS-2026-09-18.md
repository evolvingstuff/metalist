## September 19 search-redaction boundary correction

The user clarified that whole-tree selection must not admit search-redacted notes,
even if temporarily revealed or selected for editing. Review found that selection
already respected cloud blacklists and identified the edited node, but full-tree
expansion could disclose search-excluded relatives. Two new tests reproduced this
before the fix. Traversal now excludes branches outside authoritative visible-view
membership; selection does not override search or privacy restrictions.

Fifteen added deterministic checks cover search and blacklist exclusions, selected
excluded notes, content/tag/citation absence, edited-node identity, and actual tag,
negative-tag, and negative-text search resolution. The full Python unit suite
passed **1,663 tests**, with seven skipped. Existing whole-tree tests now explicitly
supply permitted relatives; the LLM scenarios and expectations remain unchanged.
No production prompt text changed, and no new live LLM run was performed for this
server-side filtering correction. The preceding 723/725 result remains historical.
